## What is BrowserPod?

BrowserPod is a WebAssembly-based API that creates a lightweight Linux virtual machine directly in a user's browser tab. Its in-browser Linux kernel supports a variety of sandboxed runtime environments, including Node.js, Rust and Python, and [Portals](/docs/understanding-browserpod/portals) provide configurable networking for controlled ingress and egress.

### Key features

<div class="not-prose grid grid-cols-1 sm:grid-cols-2 items-start gap-3 my-6">

<FeatureBox title="Kernel">
	BrowserPod compiles full native runtimes to WebAssembly, targeting a
	Linux-compliant syscall interface rather than a limited JavaScript shim.
</FeatureBox>

<FeatureBox title="Sandbox">
	Code runs inside the browser's own security boundary, isolated from the host
	operating system, with additional [cross-origin
	isolation](/docs/understanding-browserpod/cross-origin-isolation).
</FeatureBox>

<FeatureBox title="Runtimes">
	Node.js, Rust and Python (preview) all run inside the Pod, with even more
	coming soon. Node.js and Python run as full runtimes; Rust has no in-Pod
	runtime, so Rust programs are built with the [BrowserPod Rust
	toolchain](/docs/guides/installing-rust-toolchain) and the resulting Wasm
	binaries [run directly in a Pod](/docs/guides/run-programs-in-a-pod).
</FeatureBox>

<FeatureBox title="Compatibility">
	The Node.js runtime ships with npm and Vite built in, and supports most
	frameworks, including React, Angular, Next.js and Express.js. Packages that
	ship prebuilt native binaries need [a Wasm-compatible
	alternative](/docs/guides/Working-around-native-npm-dependencies). Support for
	more tooling across the Rust and Python workflows is on the way.
</FeatureBox>

<FeatureBox title="Filesystem">
	A block-based streaming [virtual
	filesystem](/docs/understanding-browserpod/filesystem) provides full POSIX
	compatibility. Disk images are streamed on demand, and file changes stay on
	the device, in the Origin Private File System (OPFS) where the browser offers
	it and IndexedDB as a fallback.
</FeatureBox>

<FeatureBox title="Portals">
	Any port opened inside a Pod can be shared through a temporary, private URL.
	[Portals](/docs/understanding-browserpod/portals) route external traffic
	directly to the service running in the browser, enabling live previews and
	collaboration without any backend servers.
</FeatureBox>

<FeatureBox title="Tools">
	Every Pod includes a wide range of developer tools, including bash/shell, git
	and coreutils, alongside runtime-specific tooling such as npm for Node.js and
	jj for Rust.
</FeatureBox>

<FeatureBox title="Databases">
	SQLite3 support is currently in beta, so a Pod can keep relational data
	locally without a database server.
</FeatureBox>

<FeatureBox title="Browser support">
	All major browsers are supported, including Chrome, Edge, Firefox and Safari.
	For exceptionally complex or experimental use cases, Chromium-based browsers
	are recommended for maximum compatibility.
</FeatureBox>

<FeatureBox title="Multithreading">
	Web Workers enable true multithreading and process isolation, running the
	multi-process workloads that would normally require a full operating system.
</FeatureBox>

</div>

## Use cases

### AI agents

BrowserPod provides a sandboxed, client-side environment for applications that write code using AI. [BrowserCode](https://browsercode.io/claude), our own BrowserPod application, runs Claude Code entirely in the browser.

### Demos

Interactive demos can be shared over a temporary, private URL using [Portals](/docs/understanding-browserpod/portals).

### Documentation

Developer tool and API documentation can be made interactive, running tutorials, examples and code snippets in the reader's browser with no execution infrastructure to host.

### Moving server processes client-side

BrowserPod can run server-side processes directly in a user's browser, reducing cloud dependencies when developing web applications.

### Web IDEs

Web IDEs can use a Pod as their development environment, running package installs, dev servers and build tools entirely on the client.

## Roadmap

Our goal is to expand BrowserPod into a language-agnostic platform throughout 2026, with planned milestones across the year:

- **Ruby** support.
- Support for **Go**.
- **Linux-class workloads** powered by CheerpX, enabling any unmodified Linux container to run in the browser.
