## What is BrowserPod?

BrowserPod is a WebAssembly-based API that creates a lightweight Linux virtual machine directly in a user's browser tab. Its in-browser Linux kernel supports a variety of sandboxed runtime environments, including Node.js, Python and Rust. BrowserPod also includes configurable networking for controlled ingress and egress.

### Key features

<div class="not-prose grid grid-cols-1 sm:grid-cols-2 items-start gap-3 my-6">

<FeatureBox title="Kernel">
	BrowserPod compiles full native runtimes to WebAssembly, targeting a
	Linux-compliant syscall interface rather than a limited JavaScript shim.
</FeatureBox>

<FeatureBox title="Sandbox">
	BrowserPod runs directly in the browser, inheriting its security boundary,
	with additional cross-origin isolation.
</FeatureBox>

<FeatureBox title="Runtimes">
	In-browser runtimes for Node.js, Rust and Python (currently in beta) with
	runtimes for Ruby and Go planned for the second half of 2026.
</FeatureBox>

<FeatureBox title="Compatibility">
	The Node.js runtime ships with npm and Vite built in, and supports most
	frameworks (including React, Angular, Next.js and Express.js; see Node.js
	frameworks for more). Rust launches with jj, with more tools coming to the
	Rust and Python runtimes soon.
</FeatureBox>

<FeatureBox title="Filesystem">
	A block-based streaming virtual filesystem provides full POSIX compatibility.
	Disk images are streamed on demand, and any file changes stay local to the
	browser session using either IndexedDB or the Origin Private File System
	(OPFS).
</FeatureBox>

<FeatureBox title="Portals">
	Ports that open in BrowserPod can be shared via a temporary private URL. This
	secure URL routes external traffic directly to the service running in the
	browser, enabling live previews and collaboration without any backend servers.
</FeatureBox>

<FeatureBox title="Tools">
	BrowserPod provides a wide range of developer tools, including bash/shell and
	git, alongside runtime-specific tooling such as npm for Node.js and jj for
	Rust.
</FeatureBox>

<FeatureBox title="Databases">
	SQLite3 support in BrowserPod is currently in beta.
</FeatureBox>

<FeatureBox title="Browser support">
	Support for all major browsers, including Chrome (and Chromium browsers),
	Firefox and Safari. For exceptionally complex or experimental use cases,
	Chromium-based browsers are recommended for maximum compatibility.
</FeatureBox>

<FeatureBox title="Multithreading">
	Web workers enable true multi-threading and process isolation for complex,
	multi-process workloads that would normally require a full operating system.
</FeatureBox>

</div>

## Uses

### AI agents

BrowserPod provides a sandboxed, client-side environment for applications that write code using AI. You can try Claude Code in our BrowserPod application, BrowserCode.

### Demos

BrowserPod can be used to share interactive demos over a private URL using its Portals feature.

### Documentation

BrowserPod can be used to make developer tool and API documentation interactive by providing a free execution environment for tutorials, examples and code snippets to run.

### Moving server processes client-side

BrowserPod can run server-side processes directly in a user's browser, reducing cloud dependencies when developing web applications.

### Web IDEs

BrowserPod supports full web IDEs, with its sandbox working as a development environment that can run complete server workloads.

## Roadmap

Our goal is to expand BrowserPod into a language-agnostic platform throughout 2026, with planned milestones across the year:

- **Ruby** support.
- Support for **Go**.
- **Linux-class workloads** powered by CheerpX, enabling any unmodified Linux container to run in the browser.
